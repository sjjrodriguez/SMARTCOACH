How they decide: a Random Forest in 30 seconds

The three models use the same algorithm, so it is worth understanding once. A Random Forest is many small decision trees that vote.

  1. Every tree sees a different slice Each tree learns from a random sample of the cyclists and a random subset of the variables, so the trees do not all think alike.
  2. Every tree votes Given a new cyclist, each tree answers with one level on its own.
  3. The votes become the percentages you see The most voted level is the answer, and its share of votes is the probability the application shows.

Honest reading. For the injury model, accuracy is lower than the baseline of always predicting the most common class, so macro-F1 is the right metric and the result is guidance, not a diagnosis. The plan classifier was trained on synthetic data built from rules for each level, so its results reflect those rules and not real cyclists.

Changes in this iteration

  1. ✓

    Daily injury check-in page removed

    Route, template and every link to it were removed; those buttons now lead to Log workout.

  2. ✓

    Estimated TSS removed

    Removed from the form, summary, list, server calculation and dashboard text. Load is always RPE × minutes.

  3. ✓

    Workout form in 2 tabs

    1. Workout and 2. Injury check. Editing a workout keeps a single tab.

  4. ✓

    Injury check filled in from the workout

    RPE, duration and fatigue come from the workout; the check is created automatically on save.

  5. ✓

    Documentation before the application

    The site opens on a documentation section: a CRISP-DM drop-down menu with one page per phase, Architecture and Project document. The Open SmartCoach button leads to the application.

  6. ✓

    Project document made clearer

    One card per model, a visual explanation of the Random Forest, and the results explained in plain words.

  7. ✓

    Safer configuration and validation, same behavior

    The database address and secret key come from the .env file, every workout field is checked on the server, the login redirect only accepts internal addresses, and errors are logged instead of shown to the user.
